The problem

An insurance agent needed to email his clients about seminars, birthdays and Open Enrollment. I didn't want to run that through CRM software, so I built a small tool that sends from his own Gmail account, so each client gets what looks like a normal one-to-one email.

My role

Built it for a working Medicare agent: gathered what he needed, set the safety rules, and built the app, its background jobs and its installer. Built with AI coding tools.

How it works

Python with a tkinter window, the Gmail API through OAuth 2.0 with the send-only scope, and openpyxl for Excel or CSV lists. Any spreadsheet column becomes a placeholder. Before a send the app removes duplicates, invalid addresses, the do-not-email list and anyone already emailed in that campaign. It sends one email at a time, 5 to 10 seconds apart, retries temporary Gmail errors, and stops at a daily limit, then resumes where it left off. Windows Task Scheduler runs scheduled, birthday and yearly sends without the app open, and PyInstaller packages it as an .exe.

  1. Client list in Excel or CSV
  2. Cleaning: duplicates, invalid addresses, do-not-email, already sent
  3. Preview with the full recipient list
  4. One email at a time from the agent's own Gmail
  5. Logged per campaign, so a re-run picks up where it stopped

What I learned

  • Ask for the smallest permission that works. The app can only send mail; it can't read the inbox. That's why the sender address is typed in, not looked up through Google.
  • Make the safe path the easy one. The biggest button sends one test email to yourself, and a real send shows the full recipient list and waits for a click.
  • Background jobs have no one to ask. Scheduled, birthday and yearly sends never open a sign-in window; if something is wrong they stop, log why and show a Windows notification.

What it shows

Turning a real person's request into a working desktop tool, using Google's sign-in safely with the narrowest permission, and designing confirmations and logs that prevent emailing the wrong people.

Limits, and what I’d do next

There's no automated test suite yet; it was checked by hand and with sandboxed runs. The duplicate and invalid-address checks run only in the main window, not yet in the background jobs. It hasn't been through a full enrollment season. The code is private because it's tied to a real agent's account.

Next. Move the list cleaning into the shared sending code so the background jobs get it too, then add automated tests.
