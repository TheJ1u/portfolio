The problem

People turning 65 get buried in mailers and TV ads, and many pick the wrong plan or miss deadlines that cost them for years. Spanish-speaking families have even fewer clear sources.

I'm a licensed agent in Utah and Wyoming. I wanted one place where people could get straight, sourced answers before talking to anyone, without a marketing team behind it and inside strict rules: an educational site can't give personalized advice.

My role

I own the site: the requirements, the architecture and compliance decisions, the accuracy of every figure, and the checks before each release. I built it with AI coding tools, starting in Lovable and moving to Claude Code. The tools write much of the code; I decide what gets built, review it, and prove it works.

Why I built it

People turning 65 get buried in mailers and TV ads. As a licensed agent in Utah and Wyoming, I wanted one place where families could get straight, sourced answers in English or Spanish before talking to anyone.

What I learned

  • More isn't better. Publishing hundreds of short articles at once got the site demoted in Google's August 2026 spam update. I took 378 thin posts out of Google's index and now publish fewer, longer ones on a steady schedule.
  • In a regulated field, predictable beats clever. The assistant only gives pre-written, reviewed answers, so it can't invent a plan recommendation.
  • Tests are how I trust AI-written code. Bugs that reached production, like a popup that crashed on open, became automated checks. Nine now run before each release.

How it works

A visit

  1. Visitor, in English or Spanish
  2. Vercel renders the page on the server (TanStack Start)
  3. A tiny route file sets the address, title and language alternates
  4. The page loads only the data it needs

In the browser

  1. Rule-based assistant with bilingual, typo-tolerant matching
  2. Accessible SVG charts with data-table twins
  3. Calculators, quizzes and plan guides

Leads and data

  1. Forms post to the site's own API
  2. Spam check that never blocks a real person
  3. Lead filed in a Google Sheet, with an email alert

Automation

  1. After each deploy, a GitHub Action tells Bing which pages changed
  2. Nine test scripts and a type check gate every release

Key decisions

An assistant that can't make things up

Every answer is pre-written and reviewed, so it can never invent a plan recommendation or decide someone's eligibility. Matching still feels natural: bilingual word stems, weighted keywords, any-order phrases and one-letter typo correction. A regression suite runs 82 realistic questions plus 476 self-checks in both languages.

Fast, with a large content library

Route files hold only configuration, and page components and large data files load per page. Each article carries its own search metadata, which removed about 420 KB of shared lookup tables from every page load.

Lead capture I own

Every form posts to the site's own API, which checks for spam and files the lead in a Google Sheet. The spam check fails open: only a definitely invalid token is rejected, so a real person is never turned away. Analytics count a lead only after the server confirms it, and a test fails the release if anything a visitor typed would reach analytics.

Compliance by design

Licensing is state by state. Nevada and Idaho pages switch every call button and contact to the agents licensed there, never claim my license, and hide plan tools that only apply in Utah and Wyoming. Reviews only appear on the pages of the agent they're about.

SEO in two languages

Every page has a canonical address, English and Spanish alternates, and structured data generated from what the page actually shows. Automated crawls check status codes, titles, one main heading per page, and that the structured data is valid.

Accessible for an older audience

Charts are built without a chart library, with a data-table twin for screen-reader and keyboard users. Text scales up on larger screens, dialogs trap and return focus, and reduced-motion settings are respected.

What went wrong, and what I changed

Bulk publishing backfired

About 500 short posts dated within days of each other came before the site's demotion in Google's August 2026 spam update. I took 378 posts (756 pages counting their Spanish versions) out of Google's index, kept them available to Bing, and switched to fewer, longer posts on a steady schedule.

A popup crashed the moment it opened

The project had no type checking at first. The first type-check run found the bug, and type checking is now a release gate.

Two pages broke after a missing import shipped

The build passed, but the pages crashed in the browser. Now a browser sweep loads every page in the sitemap before release.

The whole site once shipped as one 2.3 MB file

One misplaced export defeated code splitting. The rule is now written in the project guide that every AI session reads first.
